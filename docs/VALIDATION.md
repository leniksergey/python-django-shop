# Валидация

Три уровня: фронт (Vue), бэк (Django Forms), БД (validators). Данным из запроса не доверяем.

---

## 1. Оформление заказа

**Шаг 1 — ФИО, телефон, email**

| Поле | Проверка | Ошибка |
|---|---|---|
| ФИО | ≥2 символа, без цифр | «ФИО не должно содержать цифры» |
| Телефон | 10–15 цифр | «Телефон должен содержать 10–15 цифр» |
| Email | валидный | «Введите корректный email» |

**Шаг 2 — Доставка**

| Поле | Проверка | Ошибка |
|---|---|---|
| Тип | `ordinary` / `express` | «Выберите способ доставки» |
| Город | ≥2, без цифр | «Название города не должно содержать цифры» |
| Адрес | ≥3 символа | «Адрес слишком короткий» |

**Шаг 3 — Оплата:** выбрано `online` / `someone`.

**Шаг 4 — Подтверждение:** проверяем шаги 1–3, POST `/api/order/<id>/`.

---

## 2. Оплата

Одно поле — номер карты/счёта. Для обоих способов правила одинаковые.

| Проверка | Ошибка |
|---|---|
| Не пусто | «Укажите номер» |
| Только цифры | «Только цифры» |
| ≤ 8 символов | «Не более 8 цифр» |
| Чётное | «Номер должен быть чётным» |

Кнопка «Сгенерировать случайный счёт» — только для «Со чужого счёта», ставит 8-значное число. Сумма берётся на бэке из `order.total_cost`.

**Celery** (`process_payment`):
- Чётный и не заканчивается на 0 → `PAID`, 200
- Нечётный или заканчивается на 0 → `FAILED`, 500

Примеры: `22222222` — успех, `22222220` — ошибка, `22222221` — нечётный.

## 3. Корзина

`OrderCreateForm.clean_items`:

| Проверка | Ошибка |
|---|---|
| Список не пустой | «Корзина пуста» |
| Элемент — объект | «Элемент #N должен быть объектом» |
| Есть `id` и `count` (1–1000) | «Некорректный элемент #N» |
| Товары есть в БД | «Товары не найдены: [...]» |
| Цена > 0 | «Некорректная цена у товара X» |

Дубликаты `id` схлопываются, `count` суммируется.

## 4. HTTP-статусы

**Заказ:** 403 чужой · 409 оплачен · 400 ошибки формы · 200 успех.

**Оплата:** 404 нет · 403 чужой · 409 уже оплачен · 400 ошибки · 503 Celery недоступен · 500 payment failed · 200 успех.

## 6. Механика

- **Фронт:** `watch` в JS → при вводе вызывается `validate*`, ошибки в `errors`, показ через `v-if`.
- **Сохранение шагов:** `saveOrder()` в `order-detail.js` шлёт `POST /api/order/<id>` при каждом переходе между шагами — поэтому `deliveryType` и адрес попадают в БД до шага 4.
- **Бэк:** `form.is_valid()`. При ошибке — `{"error": "validation failed", "errors": {...}}`, 400. Фронт читает в `.catch`.
